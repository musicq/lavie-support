# lavie-support

The Lavie website, served at https://lifebar.app by Cloudflare Pages (project `lavie-site`).

- `site/`: the pages (`/`, `/help`, `/shortcut`, `/support`, `/privacy`, `/terms`), styles, icon, `_redirects`. `/shortcut` is where the app's "Get the Lavie shortcut" goes (`?from=app` picks the in-app steps); the signed file it offers is `site/shortcuts/Log in Lavie.shortcut`, forced to download by `_headers`. Its QR code is inline SVG for https://lifebar.app/shortcut.
- `site/_routes.json`: only `/api/*` runs Functions; every page is plain static (free, not counted as a request). `www.lifebar.app` and the pages.dev address are sent to `lifebar.app` by the account's Bulk Redirects, not by code.
- `functions/api/`: the app's statement-import proxy to DeepSeek. `challenge` → `attest` (App Attest key, once per install) → `session` (checks App Attest, the Lavie Plus StoreKit transaction or DeviceCheck's free try, and the person's daily AI budget) → `statement` (one chunk; records its real cost), or → `tidy` (Settings › Categories › Tidy with AI: names, entry counts and categories in, suggested clean names, moves and new categories out; a session with purpose `tidy` only spends from the daily budget and can't read statements). Alert and tidy sessions skip DeviceCheck, so each answers exactly one request (claimed atomically in `lib/proxy.js`), and an alert's text is capped at 6,000 characters. Apple's checks are in `lib/apple.js` (tests: `node --test test/*.test.mjs`). `ENFORCE_ATTEST` and `ENFORCE_DEVICE` in `wrangler.jsonc` are `"1"` (refuse what fails); set one to `"0"` to only log that check (see `npx wrangler pages deployment tail --project-name lavie-site`, or the `checks` column of `sessions`). Secrets `DEEPSEEK_API_KEY`, `IP_SALT`, `DEVICECHECK_KEY` (`npx wrangler pages secret put NAME --project-name lavie-site`); data in D1 `lavie-proxy` (`migrations/`, apply with `npx wrangler d1 migrations apply lavie-proxy --remote`); caps and limits in `wrangler.jsonc` `vars`. For `wrangler pages dev`, put the secrets in the git-ignored `.dev.vars`; a debug app build talks to it with the launch argument `-LavieProxyURL http://localhost:8799`. A changed secret takes effect on the next `npx wrangler pages deploy --branch main`.
- Who uses it: `npx wrangler d1 execute lavie-proxy --remote --command "SELECT tier, COUNT(*), SUM(imports), SUM(cost_micro)/1e6 AS usd FROM users GROUP BY tier"`.
- The root `index.html`, `privacy-policy.html` and `terms-of-use.html` are what GitHub Pages serves at musicq.github.io/lavie-support, which Lavie 1.0 and its old App Store listing linked to. Since 2.0 went live (2026-10-21) they only forward to lifebar.app/support, /privacy and /terms (meta refresh plus `location.replace`; GitHub Pages can't send a 301). Keep them: installed 1.0 copies still open those addresses.

Preview locally with `npx wrangler pages dev`, deploy with `npx wrangler pages deploy --branch main`.
